# Repo review, 2026-10-08

Scope: `frontend/`, `hosts/tauri`, `hosts/wails`, `.github/workflows`. Report only, no source changed.
Baseline: `typecheck`, `lint`, `npm test` (131 tests) and `build` all pass; `go test ./internal/...` passes.

Method: read all code in scope, ran hostile payloads (about 60 cases, with and without remote images) through
`sanitizeEmailHtml` + `buildSrcDoc` under vitest/jsdom, wrote integration repros against the real `App` + `MockMailService`,
and read the Wails v3 beta.28 source for binding behaviour. Scratch scripts lived outside the repo.

Confidence: **verified** = reproduced here; **read** = from code/library source only; **unverified** = needs a real Mac/WebKit.

## High

### F1. ReDoS in inline-style sanitiser freezes the app (remote, persistent)
- File: `frontend/src/features/mail/reader/safe-html/sanitize.ts:189` and `:198`
- Failure: `value.matchAll(/url\(\s*(['"]?)(.*?)\1\s*\)/gi)` is quadratic when a declaration holds many unclosed `url(` tokens
  (each start scans to the end of the value looking for `)`). A hostile mail with one `style="background:url(url(url(...` freezes the
  renderer. Measured (jsdom/V8, `sanitizeEmailHtml`): 20 KB -> 0.5 s, 40 KB -> 2.1 s, 80 KB -> 8.3 s, 160 KB -> 33 s; the quote
  variant `url('` x 20000 (100 KB) -> 19 s. `sanitizeEmailHtml` runs inside `useMemo` during render
  (`SafeHtmlFrame.tsx:24`), the last message of a thread is expanded by default, and selecting the thread opens it, so every open
  re-freezes the whole UI. The sender needs nothing but the ability to send mail. No size cap exists anywhere.
- Fix sketch:
  ```ts
  // cap work first
  if (style.length > 8_000) return '';
  // and replace the lazy regex with a linear scan (no backtracking)
  const URL_RE = /url\(\s*(?:"([^"]*)"|'([^']*)'|([^)'"\s][^)]*?))\s*\)/gi; // all classes exclude ')' or quote, so linear
  ```
  Also drop the second check at `:198` (`/url\(/ && !/url\(...\)/`) or make it use the same linear pattern. Add a regression test
  with `'url('.repeat(20000)` asserting < 100 ms. Consider a global byte cap on `html` before DOMPurify (for example 2 MB) with a
  "message too large, show plain text" fallback.
- Confidence: high on the quadratic behaviour (measured); medium on absolute times in WebKit (JavaScriptCore's regex engine also backtracks, constants differ).

## Medium

### F2. Load-more hot loop when a page fails (or whenever the list is shorter than the viewport)
- File: `frontend/src/features/mail/list/ThreadList.tsx:78-81` (`useLoadMoreOnScroll`)
- Failure: the effect has no dependency array and calls `fetchMore()` whenever `hasMore && !busy && scrollHeight <= clientHeight`.
  When `fetchNextPage` fails, `isFetchingNextPage` goes false and `hasNextPage` stays true, the error re-renders, the effect fires again:
  an endless retry loop. Repro: page 1 ok, every call with a cursor rejects -> **79 `getThreads` calls in 1.5 s** (jsdom, where
  `scrollHeight` is always 0; in a browser it needs a list shorter than the pane, e.g. Unread/Starred tabs with few matches, or `?offline=1`
  after page 1). With the Gmail provider this hammers the API into 429s.
- Fix sketch: stop after an error and require user intent to retry:
  ```ts
  useEffect(() => {
    if (error) return;               // pass list.isFetchNextPageError
    ...
  }, [hasMore, busy, error, itemsLength]);
  ```
  Use explicit deps (item count, `hasMore`, `busy`, `error`) instead of "every render".
- Confidence: verified.

### F3. Held key / repeated key fires an action many times (archive, trash, star toggle)
- Files: `frontend/src/features/mail/shortcuts.ts:40-60`, `frontend/src/features/mail/MailApp.tsx:172-192`
- Failure: no `e.repeat` guard and no in-flight guard. Repro: select a row, dispatch 5 keydowns for `e` before the first
  archive resolves -> `mail.archive` is called 5 times for the same thread (all `["t002"]`). With real latency, repeats arriving after the
  first resolves target the next focused row (selection collapses to focus only), so holding Delete walks down the list trashing
  threads. Held `s` alternates star/unstar. Two quick distinct presses behave the same way.
- Fix sketch:
  ```ts
  if (e.repeat) return;                       // shortcuts.ts onKey, after defaultPrevented
  // MailApp.perform: drop actions on ids that already have one in flight
  const inflight = useRef(new Set<ID>());
  const fresh = targetIds.filter((id) => !inflight.current.has(id)); ... finally delete
  ```
- Confidence: verified (call count); the walk-down-the-list consequence is read from the code path.

### F4. Wails: dock and notification services are bound to the page, contradicting the code comment
- File: `hosts/wails/main.go:62-71, 79-81`
- Failure: `application.NewService(dockSvc)` and `NewService(notifSvc)` register every exported method of those services as page-callable
  (`Bindings.Add` in Wails v3 beta.28 binds all exported methods except `ServiceName/Startup/Shutdown/ServeHTTP`). The comment says they are
  "intentionally NOT exposed to the page". In fact the page can call `HideAppIcon`, `ShowAppIcon`, `SetCustomBadge`, `SendNotification`,
  `SendNotificationWithActions`, `RemoveAllDeliveredNotifications`, ... by FQN via `Call.ByName`, bypassing `platform.Service`'s validation.
  Wails' built-in runtime also exposes clipboard, dialogs, window and quit calls to the page; these cannot be narrowed in beta.28.
  Exploitability needs script execution in the main frame (the reader iframe cannot run scripts), so this is defence in depth plus a false claim.
- Fix sketch: register lifecycle-only wrappers so no methods are bound:
  ```go
  type lifecycle struct{ svc interface{ ServiceStartup(context.Context, application.ServiceOptions) error } }
  func (l lifecycle) ServiceStartup(ctx context.Context, o application.ServiceOptions) error { return l.svc.ServiceStartup(ctx, o) }
  ... application.NewService(&lifecycle{dockSvc})
  ```
  (`ServiceStartup` is skipped by `getMethods`, so the wrapper binds nothing.) If that is awkward, at least fix the comment and document the exposure.
- Confidence: read (Wails source: `pkg/application/bindings.go:208-245`, `application.go:777`); not run on a Mac.

### F5. Unread/Starred tabs filter client-side over loaded pages only
- File: `frontend/src/features/mail/MailApp.tsx:99-114`, `ThreadList.tsx:72-81`
- Failure: the tab filter runs over whatever pages are loaded (30 per page). Consequences: tab badge counts (`filterCounts`) are counts of
  loaded rows, not mailbox totals, while the header shows the server unread count (`unreadCount`), so the two disagree; "No unread
  conversations here." appears when page 1 has none even though page 5 does; and because an empty list is not scrollable, F2's effect then
  crawls the entire mailbox page by page to fill the viewport (a full-account scan on a real Gmail account).
- Fix sketch: push the filter into the query (`ThreadQuery.unreadOnly` / `starredOnly`, mapped to `is:unread`/`is:starred` in the Gmail
  adapter) and take the tab count from `counts.data`; keep the "selected rows stay visible" behaviour locally.
- Confidence: verified by reading; the crawl follows from F2's verified behaviour.

### F6. Stale async completion overwrites newer selection
- File: `frontend/src/features/mail/MailApp.tsx:154-164`
- Failure: `perform` awaits the mutation and then unconditionally `setSelection({ selected: new Set(), focusedId: next ... })`. Repro:
  press `e` on row A (100 ms latency), immediately click row D; when the archive resolves D is deselected (selection went from 1 to 0 in
  the test). With Gmail latency (300 ms+) that is common during triage. Also the reader shows "No conversation selected" after every
  archive because selection is emptied rather than moved to `next`.
- Fix sketch: only apply if the user has not moved on:
  ```ts
  const before = selectionRef.current;           // keep a ref
  ...
  if (ok && removes) setSelection((s) => (s === before ? {selected: new Set(next ? [next] : []), focusedId: next, anchorId: next} : prune(s, ids)));
  ```
  (Decide separately whether archive should open the next thread, as Gmail does.)
- Confidence: verified.

### F7. CI never compiles the macOS code that both hosts exist for
- File: `.github/workflows/hosts.yml:21-58`
- Failure: both host jobs run on `ubuntu-latest`. `cfg(macos)` Rust paths (`set_badge_count`, `windowEffects`, `macos-private-api`), the Go
  darwin build with `-tags private_mac_apis`, and the dock/notification services are never built in CI; the README itself lists them as
  unverified. A broken darwin build lands on `main` silently. Related: the Tauri job only runs `cargo check` (no `clippy`, `fmt --check`, `cargo test`),
  and the `frontend.yml` `build` script re-runs `tsc` after the separate typecheck step.
- Fix sketch: add `macos-latest` jobs: `go vet -tags private_mac_apis ./... && go build -tags production,private_mac_apis ./...` and
  `cargo check --locked` (same job matrix with `os: [ubuntu-latest, macos-latest]`); add `cargo clippy -- -D warnings` and `cargo fmt --check`.
- Confidence: high (workflow read).

## Low

### F8. CapsLock turns plain keys into destructive shortcuts
- File: `frontend/src/features/mail/shortcuts.ts:14-23`
- `case 'I'|'U'|'Z'` match on `e.key` only, never `shiftKey`. With CapsLock on, plain `i` yields key `I` and triggers mark-read (repro: one
  `markRead` call); plain `u` marks unread and `z` restores. With CapsLock on, `e` and `s` stop working. Fix: `if (e.shiftKey && e.key.toLowerCase() === 'i') ...` and
  compare `e.key.toLowerCase()` for the unshifted ones. Confidence: verified.

### F9. Sanitiser failure takes down the whole UI; malformed styles throw under jsdom
- Files: `sanitize.ts:204-223`, `SafeHtmlFrame.tsx:24`, `App.tsx` (no error boundary anywhere in `src`)
- `<p style="width:calc(1px;background:url(x))">` makes jsdom's CSS parser throw ("`)` is expected") and `sanitizeEmailHtml` rethrows
  `TypeError: ... 'innerHTML' of null` (DOMPurify returned null). jsdom-only as far as I can tell (unverified in WebKit), but nothing catches
  a render-time throw, so one bad message blanks the app. Fix: wrap sanitize in try/catch returning `{ html: '', blockedRemoteContent: false }` plus a
  "This message could not be displayed safely" notice, and add a top-level `ErrorBoundary` in `App.tsx`. Confidence: verified (jsdom), unverified (WebKit).

### F10. CSS filter is a deny-list; unknown image functions survive
- File: `sanitize.ts:172-200`
- `background:image('http://evil/x')` is kept in blocked mode (the `image()` function never shipped, and CSP `img-src` would stop it anyway), as is
  `background: var(--x)` (harmless, the custom property is dropped). Not exploitable today because the CSP in `buildSrcDoc.ts:6` is the real wall; but any future
  CSS image function would pass. Fix: allow-list value shapes (`/^[\w\s#%.,()+\-/"']*$/` without `(`-functions outside `rgb|hsl|calc|var`) or drop every value that contains `(`
  not in a short allow-list of functions. Confidence: verified (output), exploitability none.

### F11. Links: no destination visible, `mailto:` parameters pass through
- Files: `sanitize.ts:57-64`, `SafeHtmlFrame.tsx:14,70`, `hosts/wails/internal/platform/platform.go:39-58`, `hosts/tauri/src-tauri/capabilities/default.json`
- Hostile mail can show `https://bank.example` as text and link anywhere; the app has no hover/status URL and no confirmation, and
  WKWebView in both hosts has no status bar. `mailto:a@b.c?attach=/etc/passwd&body=...` passes all three validators; some mail handlers honour
  `attach`/`attachment`. Fix: show the real host in a tooltip/confirm when link text looks like a URL with a different host; strip `attach`,
  `attachment` (and `bcc`) from `mailto:` before `openExternal`. Confidence: read; the Apple Mail behaviour is unverified.

### F12. Tauri: app commands are not ACL-gated; CSP is looser than needed
- Files: `hosts/tauri/src-tauri/build.rs`, `src/lib.rs:121`, `tauri.conf.json:39`
- `notify`, `set_badge`, `set_window_theme` are plain `generate_handler!` commands with no `AppManifest`, so any webview/frame with IPC can invoke them
  (the capability file only restricts plugin and core permissions). The CSP lacks `base-uri 'none'`, `form-action 'none'`, `object-src 'none'`, allows
  `http:` images and `data:`/`blob:` frames, none of which the app uses (the reader uses `srcdoc`). `withGlobalTauri: true` puts `__TAURI__` on the page.
  Fix: `tauri_build::Attributes::new().app_manifest(AppManifest::new().commands(&["notify","set_badge","set_window_theme"]))` and add the
  three permissions to the capability; CSP -> `img-src 'self' data: https:; frame-src 'self'; base-uri 'none'; form-action 'none'; object-src 'none'`.
  The `opener` scope (`https://*`, `http://*`, `mailto:*`) matches the frontend allow-list; consider dropping plain `http:`. Confidence: read.

### F13. `patchLists` rollback and cancel are coarse
- File: `frontend/src/features/mail/useMailActions.ts:23-39, 100-103`
- Rollback restores the whole pre-action snapshot, so if action A fails after action B patched the same lists, B's optimistic change vanishes until the
  `finally` invalidation lands. `cancelQueries` on the whole `threads` prefix also aborts an in-flight "load more" page. Fix: roll back per thread id
  (re-apply the old values for `ids` only) and cancel only the active list key, or skip cancel and use `refetch` after settle. Confidence: read.

### F14. Window-inactive tracking and the `--accent-tick` hack
- File: `frontend/src/platform/hostChrome.ts:38-49`
- `--accent-tick` is set on every focus/blur but no CSS reads it (grep: only the writer exists), so it cannot force the system-colour re-resolve its comment
  claims. The listeners are never removed (fine at app scope, but untestable). `document.hasFocus()` at startup in WKWebView can be false until the first click, which would leave
  selection gray at launch (unverified). The CSS cascade for `AccentColor` itself is correct (`:root[data-host][data-skin]` beats the skin `--accent` rules). Fix: delete the property or make a
  rule consume it; initialise the attribute from `focus` events only. Confidence: read / unverified on a Mac.

### F15. Wails smaller issues
- `hosts/wails/internal/platform/platform.go:36,82` `nextID++` is an unsynchronised counter on a service whose methods Wails invokes from separate goroutines: data race (duplicate notification IDs, `-race` would flag a concurrent test). Use `atomic.Int64`. Confidence: read.
- `hosts/wails/main.go:98` comment "Opaque by default. Vibrancy is an opt-in experiment" is stale; `ParseWindowOptions` defaults vibrancy **on**. The Taskfile
  always builds production with `private_mac_apis` on darwin, so the private API is in every release regardless of `ZUSTELLER_VIBRANCY=0`.
- Menu naming drifts between hosts: Wails "Mailbox" / "Star", Tauri "Mail" / "Add / Remove Star".

### F16. Dead code and duplicated logic
- `PlatformService.showNotification` is implemented three times plus Rust `notify` and Go `ShowNotification`, and nothing in `features/` calls it (AGENTS rule 3: no placeholder methods).
- `domain/mail/semantics.ts:17` `THREAD_SEMANTICS_VERSION` and the `buildCsp` re-export in `safe-html/index.ts:3` are unused outside tests.
- `hosts/tauri/src-tauri/Cargo.toml:19` `serde_json` is not used by any source file.
- `ThreadList.tsx:275-286`: `ThreadRow` is `memo`ed but receives fresh inline closures (`onClick`, `onToggleSelect`, `buildContextItems`...) on every render, so memo never skips.
- `useThreadActions.ts` has a stray extra `{ ... }` block inside `buildThreadActions`; `useGlobalShortcuts` re-subscribes each render (inline `onSearch`); `accentDebug.ts` ships in production builds.
- `tauri.opaque.conf.json` duplicates the window block (arrays are replaced on merge); drift risk, already noted in the README.
- Allow-list `['http:','https:','mailto:']` is repeated in `browser.ts`, `tauri.ts`, `wails.ts`, `SafeHtmlFrame.tsx`, `sanitize.ts`, Go and the Tauri capability. Centralise the TS copy in one `isSafeExternalUrl` in `platform/`.
- `.github/workflows/frontend.yml:3-5` triggers on both `push` and `pull_request` for every branch, so each PR commit runs twice (the concurrency group differs per ref). Restrict `push` to `main`.

### F17. Architecture drift and gaps worth tracking
- Feature code imports `@/platform/hostChrome`, which pulls `./tauri` and `./wails` host detection into `features/*` (`MailApp.tsx:1`, `ThreadList.tsx:1`, `Reader.tsx:1`, `Sidebar.tsx`). The lint rule only blocks `@tauri-apps/*`, so this passes; expose `dragRegionProps` through context instead.
- `cid:` images are allowed by the sanitiser and CSP but nothing resolves them, so inline images render blank; and remote `http://` images pass the sanitiser when remote content is enabled but are blocked by CSP `img-src https:`. Both are Phase 3 concerns; decide before the Gmail adapter.
- `createServices.ts` honours `?offline=1` / `?latency=` in production builds (harmless with the mock; must go before a real provider lands).

## Checked and fine
- Iframe: `sandbox="allow-same-origin"` only; click and auxclick are `preventDefault`ed and only `http(s)/mailto` reach `onOpenLink`; CSP `default-src 'none'; img-src data: cid: [https:]; style-src 'unsafe-inline'`; `referrerpolicy=no-referrer`.
- DOMPurify 3.4.16; `RETURN_DOM` plus re-serialisation showed no mutation XSS in tested vectors; `svg`, `math`, `form`, `template`, `style`, `link`, `meta`, `base` are dropped.
- Tracking pixels are removed only while blocked; remote `srcset`, `//host`, `background=` attributes and CSS `url()` are blocked until the user opts in per message.
- Go `ValidateExternalURL` rejects `javascript:`, `file:`, `data:`, `ftp:`, empty host, `//evil`; Tauri's opener scope matches. `set_window_theme` ignores unknown values.
- Tauri capability file grants only `start-dragging`, `toggle-maximize` and a scoped `opener:allow-open-url`.
- Selection model (`selection.ts`) and `nextAfterRemoval`/`prune` behave correctly; Mock keyset pagination is stable under mutation.
